mu_run 使用说明

1. 通过 JSON 人工控制 0/1 类比例

脚本位置：
utils/build_binary_resampled_labels.py

作用：
从旧标签文件中读取指定二分类标签，按目标数量生成新的标签文件：
- class 0 数量由 --num_class0 控制
- class 1 数量由 --num_class1 控制
- 当目标数量小于原始数量时，随机下采样
- 当目标数量大于原始数量时，有放回采样，相当于复制样本
- 非 0/1 的标签值（例如 -1）不会写入新文件

基本用法：
python utils/build_binary_resampled_labels.py \
  --input_json train_labels.json \
  --output_json /mnt/wangbd8/workspace/DataSets/ThyroidAgent/Classifaction_Data/Malignant_ultrasound_images_cropped/train_labels_ftcptc_3000_1000.json \
  --target_key FTCPTC \
  --num_class0 3000 \
  --num_class1 1000 \
  --seed 1024

示例：
(1) 生成 FTCPTC 训练标签，0 类 2000，1 类 1000
python utils/build_binary_resampled_labels.py \
  --input_json train_labels.json \
  --output_json train_labels_ftcptc_2000_1000.json \
  --target_key FTCPTC \
  --num_class0 2000 \
  --num_class1 1000

(2) 生成 FTCPTC 训练标签，0 类 2000，1 类 1500
python utils/build_binary_resampled_labels.py \
  --input_json train_labels.json \
  --output_json train_labels_ftcptc_2000_1500.json \
  --target_key FTCPTC \
  --num_class0 2000 \
  --num_class1 1500

说明：
- 如果 num_class1 大于原始正类数量，脚本会自动复制正类样本
- 输出文件可以直接替换训练脚本中的 TRAIN_LABEL_PATH


2. sampler 版二分类多任务训练

训练代码：
train_multitask_binary_sampler.py

核心参数：
- --train_label_path: 训练标签 JSON 文件
- --target_key: 关注的二分类标签，例如 FTCPTC
- --task_schedule: 多任务优化顺序，例如 seg,cls 或 cls,cls,seg
- --sampler_pos_fraction: WeightedRandomSampler 中正类采样比例
- --sampler_num_samples: 每个 epoch 抽样总数
- --cls_pos_weight: 分类 BCE 中正类损失权重，值越大越偏向提升 recall

当前可直接使用的脚本：
- scripts/binary/train_binary_sampler_FTCPTC_segcls_pf02_ns6000.sh
- scripts/binary/train_binary_sampler_FTCPTC_clsclsseg_pf02_ns6000.sh

2.1 seg,cls 版本
脚本位置：
scripts/binary/train_binary_sampler_FTCPTC_segcls_pf02_ns6000.sh

含义：
- task_schedule="seg,cls"
- 每个优化 step 做一次分割、一次分类
- sampler 正类比例 0.2
- sampler 总抽样数 6000
- cls_pos_weight=3

运行方式：
bash scripts/binary/train_binary_sampler_FTCPTC_segcls_pf02_ns6000.sh

如果要改训练标签文件：
把脚本中的 TRAIN_LABEL_PATH 改成新的 JSON，例如：
TRAIN_LABEL_PATH="/mnt/wangbd8/workspace/ThyroidAgent/dino_unet_multitask/train_labels_ftcptc_2000_1000.json"

如果要改 recall 倾向，优先改这两个变量：
SAMPLER_POS_FRACTION=0.2
CLS_POS_WEIGHT=3

经验：
- 想更强调 recall：可尝试把 CLS_POS_WEIGHT 调到 4
- 如果已经通过新 JSON 做了较强重采样，建议先把 CLS_POS_WEIGHT 控制在 1~3

2.2 cls,cls,seg 版本
脚本位置：
scripts/binary/train_binary_sampler_FTCPTC_clsclsseg_pf02_ns6000.sh

含义：
- task_schedule="cls,cls,seg"
- 每个优化 step 做两次分类、一次分割
- 相比 seg,cls 更偏向分类任务
- sampler 正类比例 0.2
- sampler 总抽样数 6000
- cls_pos_weight=3

运行方式：
bash scripts/binary/train_binary_sampler_FTCPTC_clsclsseg_pf02_ns6000.sh

如果要改训练标签文件：
把脚本中的 TRAIN_LABEL_PATH 改成新的 JSON，例如：
TRAIN_LABEL_PATH="/mnt/wangbd8/workspace/ThyroidAgent/dino_unet_multitask/train_labels_ftcptc_2000_1500.json"

经验：
- 如果当前模型 recall 很低，优先尝试这个脚本
- 这个版本比 seg,cls 更容易把优化重点放在分类上


3. 不依赖 sampler 的二分类多任务训练

训练脚本：
scripts/binary/train_binary_FTCPTC.sh
底层代码：
train_multitask_binary_gamtl.py

适用场景：
- 你已经通过新的 train_labels.json 人工控制了 0/1 比例
- 不想再额外使用 WeightedRandomSampler
- 想让训练集分布完全由新 JSON 决定

运行方式：
bash scripts/binary/train_binary_FTCPTC.sh

如果要改训练标签文件：
修改脚本中的 TRAIN_LABEL_PATH，例如：
TRAIN_LABEL_PATH="/mnt/wangbd8/workspace/ThyroidAgent/dino_unet_multitask/train_labels_ftcptc_2000_1500.json"

特点：
- 不需要 sampler_pos_fraction
- 不需要 sampler_num_samples
- 更适合测试“只靠新 JSON 调整样本分布”的效果

建议：
- 如果你已经在新 JSON 中明显减少了 0 类，并复制了 1 类，建议先试这个版本
- 这样更容易判断 recall 提升到底是来自数据分布变化，还是来自 sampler


4. 推荐实验顺序

方案 A：先只测试人工重采样 JSON 的效果
1) 用 utils/build_binary_resampled_labels.py 生成新 JSON
2) 修改 scripts/binary/train_binary_FTCPTC.sh 中的 TRAIN_LABEL_PATH
3) 运行 bash scripts/binary/train_binary_FTCPTC.sh

方案 B：人工重采样 JSON + sampler + pos_weight
1) 用 utils/build_binary_resampled_labels.py 生成新 JSON
2) 修改 scripts/binary/train_binary_sampler_FTCPTC_clsclsseg_pf02_ns6000.sh 中的 TRAIN_LABEL_PATH
3) 根据需要调整：
   - SAMPLER_POS_FRACTION
   - CLS_POS_WEIGHT
4) 运行 bash scripts/binary/train_binary_sampler_FTCPTC_clsclsseg_pf02_ns6000.sh


5. 参数含义速查

TRAIN_LABEL_PATH：
训练时使用的标签 JSON 文件路径

TARGET_KEY / --target_key：
当前关注的二分类标签，例如 FTCPTC 或 LNM_CN01

SAMPLER_POS_FRACTION：
WeightedRandomSampler 希望抽到的正类占比
例如 0.2 表示每个 epoch 抽样结果中，目标约 20% 为正类

SAMPLER_NUM_SAMPLES：
每个 epoch 抽样总数
例如 6000 表示每个 epoch 固定抽 6000 个样本

CLS_POS_WEIGHT：
分类 BCE loss 中正类样本权重
例如 3 表示正类错分的代价更高，训练时更偏向提升 recall

TASK_SCHEDULE：
每个 optimizer step 的任务顺序
- seg,cls：一次分割 + 一次分类
- cls,cls,seg：两次分类 + 一次分割


6. 当前建议

如果当前目标是提升 FTCPTC 的 recall，建议优先试：
- 先生成新的 train_labels JSON
- 先跑一次不带 sampler 的 train_binary_FTCPTC.sh
- 如果 recall 仍然偏低，再试：
  scripts/binary/train_binary_sampler_FTCPTC_clsclsseg_pf02_ns6000.sh

一个可作为起点的比例示例：
- num_class0 = 2000
- num_class1 = 1000 或 1500

如果用 sampler 版本，可先从下面组合开始：
- SAMPLER_POS_FRACTION=0.2
- CLS_POS_WEIGHT=2 或 3
